## 1. Classes & Objects

### What is a Class?
A **class** is a **blueprint** for creating objects. It defines what properties and behaviors an object should have.

### What is an Object?
An **object** is an **instance** of a class. It's the actual thing created from the blueprint.

### Simple Example (Beginner Level)

```java
// BLUEPRINT (Class)
public class Car {
    // Properties (what the car has)
    String color;
    String brand;
    int speed;
    
    // Behavior (what the car can do)
    void accelerate() {
        speed = speed + 10;
        System.out.println("Car is accelerating! Speed: " + speed);
    }
}

// CREATING OBJECTS (Instances)
Car myCar = new Car();      // Object 1
myCar.color = "Red";
myCar.brand = "Tesla";
myCar.accelerate();         // Output: Car is accelerating! Speed: 10

Car yourCar = new Car();    // Object 2
yourCar.color = "Blue";
yourCar.brand = "BMW";
yourCar.accelerate();       // Output: Car is accelerating! Speed: 10
```

**Key Point:** `myCar` and `yourCar` are different objects with different color and brand, even though they use the same Car class blueprint.

### How ReBook Uses It

In ReBook, **User class** is the blueprint, and each registered user is an **object**:

```java
// BLUEPRINT in auth-service
@Entity
@Table(name = "users")
public class User {
    @Id
    private Long id;
    private String name;
    private String email;
    private String password;
}

// CREATING OBJECTS (when user registers)
User user1 = new User();
user1.setName("Alice");
user1.setEmail("alice@example.com");

User user2 = new User();
user2.setName("Bob");
user2.setEmail("bob@example.com");

// Both are User objects but with different data
```

## 2. Constructors & this Keyword

### What is a Constructor?
A **constructor** is a special method that **initializes** (sets up) an object when it's created. It runs automatically when you use `new`.

### Simple Example

```java
public class Student {
    String name;
    int rollNumber;
    
    // CONSTRUCTOR (runs when you create an object)
    public Student(String name, int rollNumber) {
        this.name = name;              // 'this' = current object
        this.rollNumber = rollNumber;
    }
    
    void display() {
        System.out.println("Name: " + name + ", Roll: " + rollNumber);
    }
}

// Creating objects with constructor
Student s1 = new Student("Arjun", 101);  // Constructor runs automatically
s1.display();  // Output: Name: Arjun, Roll: 101

Student s2 = new Student("Priya", 102);
s2.display();  // Output: Name: Priya, Roll: 102
```

### What is `this`?
`this` refers to the **current object**. It helps distinguish between:
- **Parameter** (method input): `name` (local variable)
- **Property** (object variable): `this.name` (belongs to object)

### Multiple Constructors (Constructor Overloading)

```java
public class Book {
    String title;
    String author;
    int pages;
    
    // Constructor 1: Three parameters
    public Book(String title, String author, int pages) {
        this.title = title;
        this.author = author;
        this.pages = pages;
    }
    
    // Constructor 2: Two parameters
    public Book(String title, String author) {
        this.title = title;
        this.author = author;
        this.pages = 0;  // Default value
    }
    
    // Constructor 3: One parameter
    public Book(String title) {
        this.title = title;
        this.author = "Unknown";
        this.pages = 0;
    }
}

// Using different constructors
Book b1 = new Book("Clean Code", "Robert Martin", 464);
Book b2 = new Book("Java Basics", "James Gosling");
Book b3 = new Book("Design Patterns");
```

### How ReBook Uses Constructors

In ReBook, **User entity uses constructor** (generated by Lombok `@Builder`):

```java
// Traditional constructor
public User(String name, String email, String password) {
    this.name = name;
    this.email = email;
    this.password = password;
}

// Using constructor
User user = new User("Alice", "alice@example.com", "secure_password");

// Or with Lombok @Builder (cleaner)
User user = User.builder()
    .name("Alice")
    .email("alice@example.com")
    .password("secure_password")
    .build();
```

## 3. static Keyword

### What is static?
**static** means the property or method belongs to the **class itself**, not to individual objects.

### Simple Example

```java
public class Counter {
    static int count = 0;      // STATIC - shared by all objects
    String name;               // NON-STATIC - each object has its own
    
    public Counter(String name) {
        this.name = name;
        count++;  // Increment shared counter
    }
    
    static void displayCount() {
        System.out.println("Total objects created: " + count);
    }
}

// Creating objects
Counter c1 = new Counter("First");
Counter c2 = new Counter("Second");
Counter c3 = new Counter("Third");

Counter.displayCount();  // Output: Total objects created: 3
```

**Key Difference:**
```
STATIC                          | NON-STATIC
Belongs to CLASS                | Belongs to OBJECT
Shared by all objects           | Unique for each object
Called with ClassName.method()  | Called with objectName.method()
```

### More Examples

```java
public class Math {
    static final double PI = 3.14159;  // Static constant
    
    static int add(int a, int b) {
        return a + b;
    }
    
    static int multiply(int a, int b) {
        return a * b;
    }
}

// Using static methods
Math.add(5, 10);           // No object needed!
Math.multiply(3, 4);
double circumference = 2 * Math.PI * radius;  // Using static PI
```

### How ReBook Uses static

In ReBook, **JwtUtil uses static**:

```java
@Component
public class JwtUtil {
    private static final String JWT_SECRET = "your-secret-key";  // Static constant
    private static final long EXPIRATION_TIME = 900000;          // Static constant
    
    // Static method

        return Jwts.parserBuilder()
            .setSigningKey(JWT_SECRET)  // Using static constant
            .build()

            .getBody()
            .getSubject();
    }
}

// Usage (no object needed)
JwtUtil.extractEmail(token);
```

## 4. Methods

### What is a Method?
A **method** is a function (behavior) that an object can perform. It's an action.

### Simple Example

```java
public class Calculator {
    // Method with parameters and return value
    int add(int a, int b) {
        return a + b;
    }
    
    // Method with parameters but no return value
    void printResult(int result) {
        System.out.println("Result: " + result);
    }
    
    // Method with no parameters and no return value
    void greet() {
        System.out.println("Hello!");
    }
    
    // Method with no parameters but return value
    String getMessage() {
        return "This is a message";
    }
}
 
// Using methods
Calculator calc = new Calculator();
int sum = calc.add(5, 10);        // Returns 15
calc.printResult(sum);             // Output: Result: 15
calc.greet();                       // Output: Hello!
String msg = calc.getMessage();    // Returns "This is a message"
```

### Method Signature
A method signature consists of:
1. **Return type** (what it gives back)
2. **Method name** (what to call it)
3. **Parameters** (what it needs as input)

```java
public int calculateAge(int birthYear) {
        //  ↑   ↑              ↑
    // return  name       parameter
    return 2024 - birthYear;
}
```

## 5. Memory Allocation Basics

### Stack vs Heap

**STACK:**
- Stores **primitive values** (int, boolean, double, char)
- Stores **object references** (memory address)
- Faster, limited size
- Automatically cleaned up when scope ends

**HEAP:**
- Stores **actual objects**
- Slower but larger capacity
- Requires garbage collection for cleanup

### Visual Example

```java
public class MemoryExample {
    public static void main(String[] args) {
        int age = 25;           // STACK: age = 25
        
        String name = "Alice";  // STACK: name → (points to)
                                // HEAP: "Alice"
        
        User user = new User(); // STACK: user → (points to)
                                // HEAP: User object
    }
}
```

### Diagram

```
STACK (Smaller, Faster)        HEAP (Larger, Slower)
┌──────────────┐               ┌────────────────────┐
│ age = 25     │               │ "Alice"            │
│              │               │                    │
│ name ────────┼──────────────→│ String object      │
│              │               │                    │
│ user ────────┼──────────────→│ User object        │
│              │               │ {                  │
│              │               │   name: "Bob"      │
│              │               │   email: "b@x.com" │
│              │               │ }                  │
└──────────────┘               └────────────────────┘
```

### How ReBook Creates Objects

When you create a User in ReBook:

```java
// This is what happens:
User user = new User();  

// 1. HEAP: New User object is created
// 2. STACK: 'user' variable stores the address/reference
// 3. You can now access: user.getName(), user.setEmail()
```

## 6. Encapsulation (Getters & Setters)

### What is Encapsulation?
**Encapsulation** means hiding internal details and only exposing what's necessary. It protects data.

### Simple Example - WITHOUT Encapsulation (BAD)

```java
public class Account {
    public double balance;  // EXPOSED - anyone can modify!
}

// Anyone can do this:
Account acc = new Account();
acc.balance = 10000;
acc.balance = -500;  // NEGATIVE BALANCE! BUG!
acc.balance = 999999;  // Cheat!
```

**Problem:** No control over what values are set!

### Simple Example - WITH Encapsulation (GOOD)

```java
public class Account {
    private double balance;  // HIDDEN - can't access directly
    
    // GETTER - read the value
    public double getBalance() {
        return balance;
    }
    
    // SETTER - write the value with validation
    public void setBalance(double amount) {
        if (amount >= 0) {  // VALIDATION!
            balance = amount;
        } else {
            System.out.println("Balance cannot be negative!");
        }
    }
    
    public void deposit(double amount) {
        if (amount > 0) {
            balance = balance + amount;
        }
    }
    
    public boolean withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance = balance - amount;
            return true;
        }
        return false;
    }
}

// Usage
Account acc = new Account();
acc.setBalance(10000);      // OK
acc.setBalance(-500);       // REJECTED! Output: Balance cannot be negative!
acc.deposit(1000);          // OK - balance = 11000
acc.withdraw(500);          // OK - balance = 10500
```

### How ReBook Uses Encapsulation

In ReBook, **User entity has private fields with getters/setters**:

```java
@Entity

    @Id
    private Long id;
    
    private String email;
    private String password;  // NEVER expose password directly!
    private Boolean isBanned;
    
    // GETTERS

        return id;
    }
    
    public String getEmail() {
        return email;
    }
    
    public Boolean getIsBanned() {
        return isBanned;
    }
    
    // SETTERS
    public void setEmail(String email) {
        if (email != null && email.contains("@")) {  // Validation
            this.email = email;
        }
    }
    
    public void setBanned(Boolean banned) {
        this.isBanned = banned;  // Only admin should call this
    }
}
```

**Using Lombok to reduce boilerplate:**

```java

    @Id

    private Boolean isBanned;
}

// Can be used as:

```

## 7. Inheritance

### What is Inheritance?
**Inheritance** means a child class inherits properties and methods from a parent class. It's an "IS-A" relationship.

**Parent/Child Analogy:** A child inherits traits from parents (height, eye color, etc.)

### Simple Example

```java
// PARENT CLASS (General)
public class Animal {
    String name;
    
    void eat() {
        System.out.println(name + " is eating");
    }
    
    void sleep() {
        System.out.println(name + " is sleeping");
    }
}

// CHILD CLASS 1 (Specific - inherits from Animal)
public class Dog extends Animal {  // Dog IS-A Animal
    void bark() {
        System.out.println(name + " is barking");
    }
}

// CHILD CLASS 2 (Specific - inherits from Animal)
public class Cat extends Animal {  // Cat IS-A Animal
    void meow() {
        System.out.println(name + " is meowing");
    }
}

// Usage
Dog dog = new Dog();
dog.name = "Buddy";
dog.eat();      // Inherited from Animal: Buddy is eating
dog.sleep();    // Inherited from Animal: Buddy is sleeping
dog.bark();     // Own method: Buddy is barking

Cat cat = new Cat();
cat.name = "Whiskers";
cat.eat();      // Inherited from Animal: Whiskers is eating
cat.meow();     // Own method: Whiskers is meowing
```

### Types of Inheritance

#### 1. Single Inheritance
One child, one parent.

```java
public class Vehicle {
    void start() { System.out.println("Vehicle started"); }
}

public class Car extends Vehicle {  // Single inheritance
    void open() { System.out.println("Car doors open"); }
}
```

#### 2. Multi-level Inheritance
Grandparent → Parent → Child

```java
public class Animal {
    void eat() { System.out.println("Eating"); }
}

public class Mammal extends Animal {
    void sleep() { System.out.println("Sleeping"); }
}

public class Dog extends Mammal {  // Multi-level
    void bark() { System.out.println("Barking"); }
}

// Dog inherits from both Mammal and Animal
Dog dog = new Dog();
dog.eat();    // From Animal
dog.sleep();  // From Mammal
dog.bark();   // Own method
```

#### 3. Hierarchical Inheritance
One parent, multiple children.

```java
public class Shape {
    void color() { System.out.println("Color"); }
}

public class Circle extends Shape {
    void radius() { System.out.println("Has radius"); }
}

public class Rectangle extends Shape {
    void width() { System.out.println("Has width"); }
}
```

### super Keyword

`super` is used to call parent class methods.

```java
public class Vehicle {
    void start() {
        System.out.println("Vehicle started");
    }
}

public class Car extends Vehicle {
    void start() {
        super.start();  // Call parent method
        System.out.println("Car specific start logic");
    }
}

Car car = new Car();
car.start();
// Output:
// Vehicle started
// Car specific start logic
```

### How ReBook Uses Inheritance

In ReBook, **repositories extend JpaRepository**:

```java
// PARENT (provides basic CRUD operations)
public interface JpaRepository<T, ID> {
    T save(T entity);
    Optional<T> findById(ID id);
    void delete(T entity);
    List<T> findAll();
    // ... and more
}

// CHILD (inherits all parent methods)
public interface UserRepository extends JpaRepository<User, Long> {
    // Inherits: save(), findById(), delete(), findAll()
    
    // Own methods specific to User
    Optional<User> findByEmail(String email);
    List<User> findByCity(String city);
}

// Usage (you get all JpaRepository methods automatically)
UserRepository repo;
User user = repo.save(newUser);         // From parent
Optional<User> found = repo.findById(1);  // From parent
List<User> users = repo.findByCity("Delhi");  // Own method
```

## 8. Polymorphism

### What is Polymorphism?
**Polymorphism** means "many forms". The same method name can behave differently in different classes.

### Type 1: Method Overloading (Same method name, different parameters)

```java
public class Calculator {
    // Same method name, different parameters
    
    int add(int a, int b) {
        return a + b;
    }
    
    double add(double a, double b) {  // Different data type
        return a + b;
    }
    
    int add(int a, int b, int c) {    // Different number of parameters
        return a + b + c;
    }
}

Calculator calc = new Calculator();
System.out.println(calc.add(5, 10));           // Calls 1st method: 15
System.out.println(calc.add(5.5, 10.2));      // Calls 2nd method: 15.7
System.out.println(calc.add(5, 10, 15));      // Calls 3rd method: 30
```

### Type 2: Method Overriding (Child class changes parent method)

```java
// PARENT CLASS
public class Animal {
    void sound() {
        System.out.println("Some generic sound");
    }
}

// CHILD CLASS 1
public class Dog extends Animal {
    @Override
    void sound() {  // Override parent method
        System.out.println("Dog barks: Woof!");
    }
}

// CHILD CLASS 2
public class Cat extends Animal {
    @Override
    void sound() {  // Override parent method
        System.out.println("Cat meows: Meow!");
    }
}

// Same method name, different behavior
Dog dog = new Dog();
dog.sound();        // Output: Dog barks: Woof!

Cat cat = new Cat();
cat.sound();        // Output: Cat meows: Meow!

Animal animal = dog;  // Dog IS-A Animal
animal.sound();       // Still outputs: Dog barks: Woof! (Polymorphism!)
```

### How ReBook Uses Polymorphism

In ReBook, **GlobalExceptionHandler uses polymorphism** (method overloading):

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<?> handleNotFound(ResourceNotFoundException e) {
        return ResponseEntity.status(404).body("Not found: " + e.getMessage());
    }
    
    @ExceptionHandler(ValidationException.class)
    public ResponseEntity<?> handleValidation(ValidationException e) {
        return ResponseEntity.status(400).body("Validation error: " + e.getMessage());
    }
    
    @ExceptionHandler(Exception.class)
    public ResponseEntity<?> handleGeneric(Exception e) {
        return ResponseEntity.status(500).body("Internal error: " + e.getMessage());
    }
}

// Same method name "handleXXX", but Spring calls the right one based on exception type!
```

## 9. Abstraction

### What is Abstraction?
**Abstraction** means hiding unnecessary complexity and showing only essential features.

**Real-life example:** When you use an ATM, you don't need to know how it processes your request internally. You just press buttons and get money!

### Type 1: Abstract Classes

```java
// ABSTRACT CLASS (can't create object directly)
public abstract class Shape {
    abstract void draw();  // Must be implemented by child
    
    void info() {
        System.out.println("I am a shape");
    }
}

// CHILD CLASS
public class Circle extends Shape {
    @Override
    void draw() {  // Implement abstract method
        System.out.println("Drawing Circle");
    }
}

// CHILD CLASS
public class Square extends Shape {
    @Override
    void draw() {  // Implement abstract method
        System.out.println("Drawing Square");
    }
}

// Can't do: Shape shape = new Shape();  ERROR!
// Must do:
Shape circle = new Circle();
circle.draw();      // Output: Drawing Circle
```

### Type 2: Interfaces

```java
// INTERFACE (all methods are abstract by default)
public interface PaymentMethod {
    void pay(double amount);      // Abstract method
    void refund(double amount);   // Abstract method
}

// IMPLEMENTATION 1
public class CreditCard implements PaymentMethod {
    @Override
    public void pay(double amount) {
        System.out.println("Paid $" + amount + " using Credit Card");
    }
    
    @Override
    public void refund(double amount) {
        System.out.println("Refunded $" + amount + " to Credit Card");
    }
}

// IMPLEMENTATION 2
public class UPI implements PaymentMethod {
    @Override
    public void pay(double amount) {
        System.out.println("Paid $" + amount + " using UPI");
    }
    
    @Override
    public void refund(double amount) {
        System.out.println("Refunded $" + amount + " via UPI");
    }
}

// Usage
PaymentMethod payment = new CreditCard();
payment.pay(100);      // Output: Paid $100 using Credit Card

payment = new UPI();
payment.pay(100);      // Output: Paid $100 using UPI
```

### Abstract Class vs Interface

| Feature | Abstract Class | Interface |
|---------|----------------|-----------|
| Constructor | Can have | Cannot have |
| Methods | Both abstract & concrete | Only abstract (Java 8+: default) |
| Variables | Any access modifier | public static final |
| Inheritance | Single | Multiple |
| Usage | "IS-A" relationship | "CAN-DO" ability |

### How ReBook Uses Abstraction

In ReBook, **repository interfaces use abstraction**:

```java
// ABSTRACTION - Interface shows what methods are available
public interface BookRepository extends JpaRepository<Book, Long> {
    List<Book> findByStatus(BookStatus status);
    List<Book> findByCategory(BookCategory category);
}

// You don't know HOW it works (SQL details hidden)
// You just know WHAT it does (finds books by status)

// Usage
List<Book> availableBooks = bookRepository.findByStatus(BookStatus.AVAILABLE);
// The complex SQL query is hidden inside the implementation!
```

Another example - **Service layer provides abstraction**:

```java
// ABSTRACT SERVICE - clients don't know implementation
@Service
public class BookService {
    public Book getBook(Long id) {
        // Complex logic hidden:
        // - Query database
        // - Check cache
        // - Handle errors
        // But client just calls: service.getBook(1);
    }
}
```

### Q1: Difference between Class and Object

**Answer:**
```
CLASS                           | OBJECT
Blueprint                       | Instance of blueprint
Logical entity                  | Physical entity
Declared once                   | Multiple objects can be created
Doesn't allocate memory         | Allocates memory when created
```

**Example:**
```java
// CLASS (Blueprint)
public class Car {
    String color;
    void drive() { }
}

// OBJECTS (Actual things)
Car car1 = new Car();  // Object 1

car1.color = "Red";
car2.color = "Blue";
// Same class, different objects with different data
```

### Q2: Constructor vs Method

**Answer:**
```
CONSTRUCTOR                     | METHOD
Special method                  | Regular method
Runs automatically at creation  | Runs when called
Same name as class              | Any name
No return type                  | Must have return type
Used to initialize              | Used for actions
```

```java
public class Student {
```

### Q3: static vs non-static

**Answer:**
```
STATIC                          | NON-STATIC
Belongs to CLASS                | Belongs to OBJECT
Shared by all objects           | Unique for each object
One copy for all objects        | Separate copy per object
Called with ClassName.method()  | Called with objectName.method()
```

**Example:**
```java
public class Employee {
    static int totalEmployees = 0;  // Shared - one for all
    String name;                     // Unique - each employee has their own
    
    public Employee(String name) {
        this.name = name;
        totalEmployees++;  // Increment shared counter
    }
    
    static void printTotal() {
        System.out.println("Total: " + totalEmployees);
    }
    
    void printName() {
        System.out.println("Name: " + name);
    }
}

Employee e1 = new Employee("Alice");
Employee e2 = new Employee("Bob");

Employee.printTotal();      // Output: Total: 2 (static - no object needed)
e1.printName();             // Output: Name: Alice (non-static - needs object)
e2.printName();             // Output: Name: Bob
```

### Q4: Why Java Doesn't Support Multiple Inheritance with Classes

**Answer:** Because of the **Diamond Problem**.

```java
// DON'T DO THIS (Not allowed in Java)
public class A {
    void show() { System.out.println("A"); }
}

public class B extends A {
    void show() { System.out.println("B"); }
}

public class C extends A {
    void show() { System.out.println("C"); }
}

public class D extends B, C {  // ERROR! Multiple inheritance not allowed!
}

// PROBLEM: Which show() should D use? B's or C's? Ambiguity!
```

**The Diamond Problem:**
```
      A
     / \
    B   C
     \ /
      D

If D extends both B and C, and both extend A:
- D has TWO copies of A's methods
- Ambiguity: which one to use?
```

**Solution: Use Interfaces (Multiple implementation)**

```java
public interface PaymentMethod {
    void pay();
}

public interface Trackable {
    void track();
}

// A class CAN implement multiple interfaces
public class CreditCard implements PaymentMethod, Trackable {
    @Override
    public void pay() { }
    
    @Override
    public void track() { }
}
```

### Q5: Abstract Class vs Interface

**Answer:**

| Feature | Abstract Class | Interface |
|---------|----------------|-----------|
| **Purpose** | Common behavior | Contract/Agreement |
| **Constructor** | ✅ Can have | ❌ Cannot have |
| **Constructor Call** | super() needed | Not applicable |
| **Methods** | ✅ Concrete methods | ❌ Only abstract (before Java 8) |
| **State** | ✅ Instance variables | ❌ Only constants |
| **Access Modifier** | Various | public only |
| **Multiple Inherit** | ❌ Single | ✅ Multiple |
| **Keyword** | extends | implements |
| **When to use** | "IS-A" relation | "CAN-DO" ability |

**Example:**

```java
// ABSTRACT CLASS - Common behavior among related classes
public abstract class Vehicle {
    abstract void start();
    
    void stop() {  // Concrete method
        System.out.println("Vehicle stopped");
    }
}

// INTERFACE - Define capabilities/contracts
public interface Chargeable {
    void charge();
}

// Usage
public class ElectricCar extends Vehicle implements Chargeable {
    @Override
    void start() { System.out.println("Electric start"); }
    
    @Override
    public void charge() { System.out.println("Charging..."); }
}
```

### Q6: Overloading vs Overriding

**Answer:**

| Feature | Overloading | Overriding |
|---------|------------|-----------|
| **What** | Same method name, different parameters | Same method name & signature in child class |
| **Parameters** | Must be different | Must be same |
| **Return type** | Can be different | Must be same |
| **Relationship** | Same class or inheritance | Only in inheritance |
| **Keyword** | None | @Override annotation |
| **Resolution** | Compile-time (Static) | Runtime (Dynamic) |

**Example:**

```java
// OVERLOADING - Same method name, different parameters
public class Math {
    int add(int a, int b) {
        return a + b;
    }
    
    double add(double a, double b) {  // Different parameter type
        return a + b;
    }
    
    int add(int a, int b, int c) {    // Different number of parameters
        return a + b + c;
    }
}

Math m = new Math();
m.add(5, 10);          // Calls 1st method
m.add(5.5, 10.2);      // Calls 2nd method
m.add(5, 10, 15);      // Calls 3rd method


// OVERRIDING - Child class provides its own implementation
public class Animal {
    void sound() {
        System.out.println("Generic sound");
    }
}

public class Dog extends Animal {
    @Override
    void sound() {  // Same signature, different implementation
        System.out.println("Woof!");
    }
}

Dog dog = new Dog();
dog.sound();  // Output: Woof! (Override method is called)
```

### Exercise 1: Bank System (Encapsulation + Validation)

```java
public class BankAccount {
    private double balance;
    private String accountHolder;
    
    public BankAccount(String accountHolder, double initialBalance) {
        this.accountHolder = accountHolder;
        if (initialBalance > 0) {
            this.balance = initialBalance;
        }
    }
    
    public void deposit(double amount) {
        if (amount > 0) {
            balance = balance + amount;
            System.out.println("Deposited: $" + amount);
        } else {
            System.out.println("Invalid amount");
        }
    }
    
    public boolean withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance = balance - amount;
            System.out.println("Withdrawn: $" + amount);
            return true;
        } else {
            System.out.println("Insufficient balance or invalid amount");
            return false;
        }
    }
    
    public double getBalance() {
        return balance;
    }
    
    public String getAccountHolder() {
        return accountHolder;
    }
}

// Usage
BankAccount acc = new BankAccount("Alice", 10000);
acc.deposit(5000);      // Deposited: $5000
acc.withdraw(2000);     // Withdrawn: $2000
System.out.println("Balance: $" + acc.getBalance());  // Balance: $13000
```

### Exercise 2: Employee Hierarchy (Inheritance)

```java
// PARENT CLASS
public class Employee {
    String name;
    double salary;
    
    public Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }
    
    void work() {
        System.out.println(name + " is working");
    }
    
    double getSalary() {
        return salary;
    }
}

// CHILD CLASS
public class Manager extends Employee {
    int teamSize;
    
    public Manager(String name, double salary, int teamSize) {
        super(name, salary);  // Call parent constructor
        this.teamSize = teamSize;
    }
    
    void manageteam() {
        System.out.println(name + " is managing " + teamSize + " people");
    }
    
    @Override
    double getSalary() {  // Override parent method
        return salary * 1.5;  // Managers get 50% bonus
    }
}

// CHILD CLASS
public class Developer extends Employee {
    String language;
    
    public Developer(String name, double salary, String language) {
        super(name, salary);
        this.language = language;
    }
    
    void code() {
        System.out.println(name + " is coding in " + language);
    }
}

// Usage
Employee emp = new Developer("Bob", 50000, "Java");
emp.work();  // Bob is working

Developer dev = (Developer) emp;
dev.code();  // Bob is coding in Java

Manager mgr = new Manager("Alice", 70000, 5);
mgr.work();  // Alice is working
mgr.manageteam();  // Alice is managing 5 people
System.out.println("Manager salary: $" + mgr.getSalary());  // Manager salary: $105000
```

### Exercise 3: Vehicle Hierarchy (Abstraction + Polymorphism)

```java
// ABSTRACT CLASS
public abstract class Vehicle {
    String name;
    
    public Vehicle(String name) {
        this.name = name;
    }
    
    abstract void start();
    abstract void drive();
    
    void stop() {
        System.out.println(name + " stopped");
    }
}

// CONCRETE CHILD 1
public class Car extends Vehicle {
    public Car(String name) {
        super(name);
    }
    
    @Override
    void start() {
        System.out.println(name + " car engine started");
    }
    
    @Override
    void drive() {
        System.out.println(name + " car is driving");
    }
}

// CONCRETE CHILD 2
public class Bike extends Vehicle {
    public Bike(String name) {
        super(name);
    }
    
    @Override
    void start() {
        System.out.println(name + " bike engine started");
    }
    
    @Override
    void drive() {
        System.out.println(name + " bike is riding");
    }
}

// Usage (Polymorphism)
List<Vehicle> vehicles = new ArrayList<>();
vehicles.add(new Car("Tesla"));
vehicles.add(new Bike("Honda"));

for (Vehicle v : vehicles) {

    v.drive();
    v.stop();
}

// Tesla car engine started

// Honda bike engine started
```
